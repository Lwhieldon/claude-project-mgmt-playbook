# Deliverable QA workflow

## Use when
- Reviewing decks, documents, or trackers before client submission.
- Confirming acceptance criteria coverage and unresolved risks.

## Procedure
1. Identify deliverable type and intended audience.
2. Check structure: purpose, scope, assumptions, findings, and decisions.
3. Verify traceability to source inputs (SOW, requirements, meeting notes).
4. Flag unclear statements, unsupported claims, and missing owners/dates.
5. Produce:
   - QA scorecard (Complete / Needs Revision)
   - Priority fixes (P1/P2)
   - Submission readiness recommendation

## Output format
- `Readiness verdict` (one line)
- `Findings table` with Issue, Severity, Suggested Fix, Owner
- `Final pre-send checklist` (5 bullets max)
